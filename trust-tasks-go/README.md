# trust-tasks-go

Go bindings for the [Trust Tasks](https://trusttasks.org) framework: a generated
payload type for every specification in the registry, and the hand-written
SPEC.md §7.2 consumer pipeline that makes those types mean something.

One of the four reference implementations, alongside
[`trust-tasks-rs`](https://crates.io/crates/trust-tasks-rs),
[`@openvtc/trust-tasks`](https://www.npmjs.com/package/@openvtc/trust-tasks) and
[`trust_tasks`](https://pub.dev/packages/trust_tasks) (Dart). All of them must
reach the same verdict on the same document; `npm run check-bindings` is what
holds them to it.

```sh
go get github.com/trustoverip/dtgwg-trust-tasks-tf/trust-tasks-go
```

Requires the Go version in this module's `go.mod` or later (the package types
are generic over the payload).
**No dependencies** beyond the standard library — the cryptosuite and the JSON
Schema engine are yours to choose, so this module declares interfaces for them
and implements neither.

> **The prebuilt packages under `specs/` are deprecated** (all but the
> framework's own `trust-task-*` ones) and will be removed in a future release.
> Pin the tasks you use with the `trust-tasks` CLI and generate them with
> `cmd/trust-tasks-gen` — see [Generating only the tasks you use](#generating-only-the-tasks-you-use).
> gopls and staticcheck (SA1019) flag an import of a deprecated package.

## Installing the `trust-tasks` command

Pinning tasks and generating their types uses the `trust-tasks` CLI, one
binary for every language. **No Rust toolchain is needed** — any one of:

- download the archive for your platform (Linux x86_64/aarch64, Windows
  x86_64; on macOS use `cargo binstall` or `cargo install`) from a
  [`trust-tasks-cli-v*` release](https://github.com/trustoverip/dtgwg-trust-tasks-tf/releases?q=trust-tasks-cli&expanded=true), check it against its `.sha256`, and
  put `trust-tasks` on your `PATH`;
- `cargo binstall trust-tasks-cli` (the same prebuilt archive);
- `cargo install trust-tasks-cli` (builds from source, Rust 1.95+).

See [GETTING-STARTED](https://github.com/trustoverip/dtgwg-trust-tasks-tf/blob/main/GETTING-STARTED.md#installing-the-trust-tasks-command) for the
commands.

## What you bring yourself

| | |
|---|---|
| Payload validator (SPEC §7.2 item 2) | yours — any JSON Schema engine behind `PayloadValidator`, fed `PayloadSchemaJSON` |
| Proof verifier / signer (item 6) | [`trust-tasks-go/proof`](./proof) — `eddsa-jcs-2022`, `ecdsa-jcs-2019`, `did:key`, standard library only |
| Transport | DIDComm v2.1: [`trust-tasks-go/didcomm`](./didcomm). TSP: [`trust-tasks-go/tsp`](./tsp) (not yet tagged). HTTPS has no package yet — use `net/http` per the [HTTPS binding](../bindings/https) |

## Layout

| Path | What it is |
|---|---|
| `trusttasks/` | Hand-written. The document envelope, the §7.2 pipeline, the error codes, the replay guard, the transport seam. |
| `specs/<slug>/v<MAJOR>_<MINOR>/` | Generated by `scripts/build-go-bindings.mjs`. **Do not edit.** The prebuilt packages — deprecated, except the framework's own. |
| `cmd/trust-tasks-gen/` | The consumer-side generator: writes the packages for the task versions a `trust-tasks.lock` pins ([below](#generating-only-the-tasks-you-use)). |
| `smoke/` | A test that drives a generated package through the real pipeline. |

Four nested modules sit beside the core, each its own Go module so the core
keeps no dependencies:

| Module | What it is | Released |
|---|---|---|
| [`proof/`](proof) | Data Integrity proofs (`eddsa-jcs-2022`, `ecdsa-jcs-2019`), standard library only | on its own `trust-tasks-go/proof/vX.Y.Z` tags |
| [`didcomm/`](didcomm) | The DIDComm v2.1 binding (authcrypt), standard library only | on its own `trust-tasks-go/didcomm/vX.Y.Z` tags |
| [`capabilityclient/`](capabilityclient) | Capability / `git-trust` document builders and reply classification, no crypto | on its own `trust-tasks-go/capabilityclient/vX.Y.Z` tags |
| [`tsp/`](tsp) | The TSP binding, on `affinidi-tsp-go` | not yet — its dependency has no tag |

Each generated package is named for its slug and version, so imports need no
alias and no two of them collide in one file:

```go
import (
    aclgrantv0_3 "github.com/trustoverip/dtgwg-trust-tasks-tf/trust-tasks-go/specs/acl/grant/v0_3"
    "github.com/trustoverip/dtgwg-trust-tasks-tf/trust-tasks-go/trusttasks"
)
```

and exports a uniform surface:

| Identifier | |
|---|---|
| `Payload`, `Response` | the request and response payload structs |
| `TypeURI`, `ResponseTypeURI` | the Trust Task type URIs (`ResponseTypeURI` only where the specification defines a success response — SPEC §4.4.1) |
| `PayloadSchemaJSON`, `ResponsePayloadSchemaJSON` | the payload schema as JSON text, cross-file `$ref`s already inlined |
| `Spec`, `ResponseSpec` | `trusttasks.SpecPolicy` values carrying the §7.2 policy flags and the schema above |

## Consuming a document

`ConsumeInbound` runs SPEC §7.2 items 2–8, plus the two stateful checks — the
duplicate-execution record of item 11 and the freshness bound of item 13 — and
then either calls your handler or builds the correctly-routed error response per
§8.1. (The examples import the prebuilt `specs/` package for brevity; a package
`cmd/trust-tasks-gen` generated has the same identifiers.)

```go
// One guard per consumer, not one per document: it IS the record.
guard := trusttasks.NewInMemoryReplayGuard(0)

outcome, err := trusttasks.ConsumeInbound(ctx,
    trusttasks.ConsumeOptions[aclgrantv0_3.Payload, aclgrantv0_3.Response]{
        Transport:     transport,
        Spec:          aclgrantv0_3.Spec,
        ProofPolicy:   trusttasks.ProofPolicy{Kind: trusttasks.ProofVerify, Verifier: myVerifier},
        PayloadPolicy: trusttasks.PayloadPolicy{Kind: trusttasks.PayloadValidate, Validator: mySchemaEngine},
        // acl/grant is consequential: a replayed envelope must not grant twice.
        Checks:     trusttasks.ConsequentialChecks(guard),
        Doc:        doc,
        MyVID:      "did:web:maintainer.example",
        Now:        time.Now(),
        NewErrorID: newID,
        Handler: func(
            ctx context.Context,
            doc *trusttasks.Document[aclgrantv0_3.Payload],
            parties trusttasks.ResolvedParties,
        ) (*trusttasks.Document[aclgrantv0_3.Response], error) {
            entry, err := applyGrant(ctx, doc.Payload.Entry, parties)
            if err != nil {
                return nil, err // aborts; or return trusttasks.Refuse(...) to answer
            }
            return trusttasks.RespondWith[aclgrantv0_3.Payload, aclgrantv0_3.Response](
                doc, newID(), aclgrantv0_3.Response{Entry: entry}, nil,
            ), nil
        },
    })
if err != nil {
    return err // a caller mistake or a handler error — not a framework rejection
}

switch outcome.Kind {
case trusttasks.OutcomeHandled:
    emit(outcome.Response)
case trusttasks.OutcomeRejected:
    emit(outcome.Error) // already addressed per §8.1
case trusttasks.OutcomeSuppressed:
    log.Printf("suppressed: %s", outcome.Reason.Code) // §8.1 — no response may be emitted
case trusttasks.OutcomeAccepted:
    // fire-and-forget (§4.4.1): nothing to emit
case trusttasks.OutcomeDuplicate:
    // §7.2 item 11 — already executed. NOT an error.
    if outcome.PriorResponse != nil {
        emit(outcome.PriorResponse)
    }
}
```

`NewErrorID` is any function returning a fresh, unique identifier; the module
has no dependencies, so it brings no UUID package. With the standard library:

```go
// newID returns a random (version 4) urn:uuid identifier.
func newID() string {
    var b [16]byte
    if _, err := rand.Read(b[:]); err != nil { // crypto/rand
        panic(err) // never mint an all-zero id: it would collide in the peer's replay record
    }
    b[6] = b[6]&0x0f | 0x40
    b[8] = b[8]&0x3f | 0x80
    return fmt.Sprintf("urn:uuid:%x-%x-%x-%x-%x", b[0:4], b[4:6], b[6:8], b[8:10], b[10:])
}
```

`PayloadPolicy` and `Checks` are **required**, and an unset one is an error
rather than a default. Both have a zero value that reads as "skip it", and
defaulting to skipping would silently reproduce the defects they exist to
remove: a payload nobody validated, and a consequential task executed twice by
an ordinary mediator retry.

## Two things the generated types do not do

**They carry no schema constraints.** No `minLength`, no `pattern`, no `minimum`,
and no `oneOf` mutual exclusion — `auth/revoke-session`'s "`sessionId` xor `all`"
is a struct with both members optional. This matches the TypeScript bindings
exactly, and it is why `PayloadSchemaJSON` ships with every package: SPEC §7.2
item 2 is where those rules are enforced, and you enforce them by handing that
schema to a JSON Schema engine through `PayloadValidator`.

**`encoding/json` enforces less than it looks like it does.** It ignores unknown
members and does not require a single REQUIRED one, so a payload missing
everything unmarshals cleanly into a generated struct. Go is closer to
TypeScript than to Rust here; run a validator.

**Member names are matched exactly — more strictly than the other runtimes.**
`encoding/json` matches a member to a field without regard to case, so
`"Issuer"` would be read as `issuer`. Decoding a `Document` (and a `Proof`)
therefore refuses a member whose name differs from a declared one only by case,
envelope and payload alike; call `trusttasks.CheckMemberNames[T]` when you decode
a payload yourself. Rust, TypeScript and Dart keep such a member as an
unrecognised one, so a Go consumer refuses `{"issuer":"a","Issuer":"b"}` where
they accept it with issuer `"a"`. A name differing in any other way
(`"thread_id"`) is an ordinary unrecognised member everywhere.

## Absent is not empty

Optional members are pointers, including optional slices and maps. `*[]string` is
awkward to hold, and it is deliberate: `omitempty` on a plain slice drops an
empty one from the wire, collapsing "present and empty" into "absent". Several
specifications make that distinction load-bearing — `vta/contexts/update`'s
`signableKeys` means "every key the context holds" when absent and "no keys" when
present-but-empty, two opposite instructions a consumer must not collapse (the
smoke test pins it), and `acl/grant/0.1`'s `allowedKeys` warned that collapsing
them "re-creates the empty-means-unrestricted class of privilege-escalation
defect this family's conventions exist to prevent". Rust spells this `Option<Vec<T>>` and TypeScript
`scopes?: string[]`; a bare Go slice was the only one of the three that could not
say it.

Unrecognized **top-level** members survive a round trip in `Document.Extra`, per
the §7.1 / §7.2 guidance to preserve them.

## Generating only the tasks you use

An application can generate the packages for just the task versions it pins,
instead of importing them from `specs/`. Lock them with the `trust-tasks` CLI
(which writes `trust-tasks.lock` and vendors each version's registry bundle
under `trust-tasks/`), then:

```go
//go:generate go run github.com/trustoverip/dtgwg-trust-tasks-tf/trust-tasks-go/cmd/trust-tasks-gen --lock trust-tasks.lock --out internal/tasks
```

`go generate` verifies every vendored bundle against its locked digest and
writes `internal/tasks/<slug>/v<M>_<N>/payload.go` — the same `Payload`,
`Response`, `TypeURI`, `Spec`, `PayloadSchemaJSON`, … as the package under
`specs/` — plus `internal/tasks/trusttasks.go`, whose `ExtendsOf` is an
`ExtendsLookup` for `trusttasks.ReadForSpecWith`. The generator is standard
library only, reads no network, and owns its out directory (it refuses to
clear a non-empty one it did not write). A task from a third-party source in
the lock is generated under `internal/tasks/<source>/…`. See
[`examples/consumer-app-go`](../examples/consumer-app-go).

## Regenerating

From the repository root:

```sh
npm run build-go-bindings
```

The generator formats its own output, so `gofmt` must be on your PATH. The
`bindings-drift` job in `.github/workflows/go.yml` fails if the committed tree
differs from what the generator produces.

A change under `specs/` must regenerate **all four** libraries (Rust,
TypeScript, Go and Dart) in the same PR — see the repository `CLAUDE.md`.

## Releasing

Do not edit `Version` in `trusttasks/version.go`. A Go module is published by
tagging: merging the repository's single Release PR (on the `release` branch) is
what pushes `trust-tasks-go/vX.Y.Z`, after which `proxy.golang.org` serves it.
See [`RELEASING.md`](https://github.com/trustoverip/dtgwg-trust-tasks-tf/blob/main/RELEASING.md).
