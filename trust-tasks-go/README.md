# trust-tasks-go

Go bindings for the [Trust Tasks](https://trusttasks.org) framework: a generated
payload type for every specification in the registry, and the hand-written
SPEC.md §7.2 consumer pipeline that makes those types mean something.

The third of three reference implementations, alongside
[`trust-tasks-rs`](../trust-tasks-rs) and
[`@openvtc/trust-tasks`](../trust-tasks-ts). All three must reach the same
verdict on the same document; `npm run check-bindings` is what holds them to it.

```sh
go get github.com/trustoverip/dtgwg-trust-tasks-tf/trust-tasks-go
```

Requires Go 1.24 or later (the package types are generic over the payload).
**No dependencies** beyond the standard library — the cryptosuite and the JSON
Schema engine are yours to choose, so this module declares interfaces for them
and implements neither.

## Layout

| Path | What it is |
|---|---|
| `trusttasks/` | Hand-written. The document envelope, the §7.2 pipeline, the error codes, the replay guard, the transport seam. |
| `specs/<slug>/v<MAJOR>_<MINOR>/` | Generated by `scripts/build-go-bindings.mjs`. **Do not edit.** |

Each generated package is named for its slug and version, so imports need no
alias and no two of them collide in one file:

```go
import (
    aclgrantv0_1 "github.com/trustoverip/dtgwg-trust-tasks-tf/trust-tasks-go/specs/acl/grant/v0_1"
    "github.com/trustoverip/dtgwg-trust-tasks-tf/trust-tasks-go/trusttasks"
)
```

and exports a uniform surface:

| Identifier | |
|---|---|
| `Payload`, `Response` | the request and response payload structs |
| `TypeURI`, `ResponseTypeURI` | the Trust Task type URIs (`ResponseTypeURI` only where the specification defines a success response — SPEC §4.4.1) |
| `PayloadSchemaJSON`, `ResponsePayloadSchemaJSON` | the payload schema as JSON text, cross-file `$ref`s already inlined |
| `Spec`, `ResponseSpec` | `trusttasks.SpecPolicy` values carrying the §7.2 policy flags and the schema above |

## Consuming a document

`ConsumeInbound` runs SPEC §7.2 items 2 and 4–8, plus the two stateful checks —
the freshness bound of item 4 and the duplicate-execution record of item 11 —
and then either calls your handler or builds the correctly-routed error response
per §8.1.

```go
// One guard per consumer, not one per document: it IS the record.
guard := trusttasks.NewInMemoryReplayGuard(0)

outcome, err := trusttasks.ConsumeInbound(ctx,
    trusttasks.ConsumeOptions[aclgrantv0_1.Payload, aclgrantv0_1.Response]{
        Transport:     transport,
        Spec:          aclgrantv0_1.Spec,
        ProofPolicy:   trusttasks.ProofPolicy{Kind: trusttasks.ProofVerify, Verifier: myVerifier},
        PayloadPolicy: trusttasks.PayloadPolicy{Kind: trusttasks.PayloadValidate, Validator: mySchemaEngine},
        // acl/grant is consequential: a replayed envelope must not grant twice.
        Checks:     trusttasks.ConsequentialChecks(guard),
        Doc:        doc,
        MyVID:      "did:web:maintainer.example",
        Now:        time.Now(),
        NewErrorID: func() string { return uuid.NewString() },
        Handler: func(
            ctx context.Context,
            doc *trusttasks.Document[aclgrantv0_1.Payload],
            parties trusttasks.ResolvedParties,
        ) (*trusttasks.Document[aclgrantv0_1.Response], error) {
            entry, err := applyGrant(ctx, doc.Payload.Entry, parties)
            if err != nil {
                return nil, err // aborts; or return trusttasks.Refuse(...) to answer
            }
            return trusttasks.RespondWith[aclgrantv0_1.Payload, aclgrantv0_1.Response](
                doc, uuid.NewString(), aclgrantv0_1.Response{Entry: entry}, nil,
            ), nil
        },
    })
if err != nil {
    return err // a caller mistake or a handler error — not a framework rejection
}

switch outcome.Kind {
case trusttasks.OutcomeHandled:
    emit(outcome.Response)
case trusttasks.OutcomeRejected:
    emit(outcome.Error) // already addressed per §8.1
case trusttasks.OutcomeSuppressed:
    log.Printf("suppressed: %s", outcome.Reason.Code) // §8.1 — no response may be emitted
case trusttasks.OutcomeAccepted:
    // fire-and-forget (§4.4.1): nothing to emit
case trusttasks.OutcomeDuplicate:
    // §7.2 item 11 — already executed. NOT an error.
    if outcome.PriorResponse != nil {
        emit(outcome.PriorResponse)
    }
}
```

`PayloadPolicy` and `Checks` are **required**, and an unset one is an error
rather than a default. Both have a zero value that reads as "skip it", and
defaulting to skipping would silently reproduce the defects they exist to
remove: a payload nobody validated, and a consequential task executed twice by
an ordinary mediator retry.

## Two things the generated types do not do

**They carry no schema constraints.** No `minLength`, no `pattern`, no `minimum`,
and no `oneOf` mutual exclusion — `auth/revoke-session`'s "`sessionId` xor `all`"
is a struct with both members optional. This matches the TypeScript bindings
exactly, and it is why `PayloadSchemaJSON` ships with every package: SPEC §7.2
item 2 is where those rules are enforced, and you enforce them by handing that
schema to a JSON Schema engine through `PayloadValidator`.

**`encoding/json` enforces less than it looks like it does.** It ignores unknown
members and does not require a single REQUIRED one, so a payload missing
everything unmarshals cleanly into a generated struct. Go is closer to
TypeScript than to Rust here; run a validator.

## Absent is not empty

Optional members are pointers, including optional slices and maps. `*[]string` is
awkward to hold, and it is deliberate: `omitempty` on a plain slice drops an
empty one from the wire, collapsing "present and empty" into "absent". Several
specifications make that distinction load-bearing — `acl`'s `allowedKeys`
documents at length that "PRESENT-BUT-EMPTY means authorized on NO keys — the
opposite of absent", and that collapsing the two "re-creates the
empty-means-unrestricted class of privilege-escalation defect this family's
conventions exist to prevent". Rust spells this `Option<Vec<T>>` and TypeScript
`scopes?: string[]`; a bare Go slice was the only one of the three that could not
say it.

Unrecognized **top-level** members survive a round trip in `Document.Extra`, per
the §7.1 / §7.2 guidance to preserve them.

## Regenerating

From the repository root:

```sh
npm run build-go-bindings
```

The generator formats its own output, so `gofmt` must be on your PATH. The
`bindings-drift` job in `.github/workflows/go.yml` fails if the committed tree
differs from what the generator produces.

A change under `specs/` must regenerate **all three** libraries in the same PR —
see the repository `CLAUDE.md`.

## Releasing

Do not edit `Version` in `trusttasks/version.go`. A Go module is published by
tagging: merging the `release-go` Release PR is what pushes
`trust-tasks-go/vX.Y.Z`, after which `proxy.golang.org` serves it. See
[`RELEASING.md`](../RELEASING.md).
